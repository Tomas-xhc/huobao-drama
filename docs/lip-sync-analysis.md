# 配音与视频口型同步分析

## 结论

**当前系统不支持口型同步。** 这是系统设计层面的缺失，不是 bug。

---

## 当前流程

系统采用"先生成视频，再叠加音频"的独立流程：

```
① AI 视频生成（MiniMax / 火山引擎 / Vidu / 阿里云）
   输入：image_prompt / video_prompt（纯文字描述）
   输出：视频文件（角色动作、口型由模型自行决定，不受音频控制）

② MiniMax TTS 语音生成（独立过程）
   输入：对白文字
   输出：MP3 音频文件

③ FFmpeg 合成（ffmpeg-compose.ts）
   仅做机械叠加：视频轨 + 音频轨 + 字幕烧录
   → 输出 MP4
```

视频生成与音频生成**完全独立**，视频里角色的嘴部动作是 AI 根据动作描述自然生成的，与后期叠加的配音没有任何同步关系。

---

## 实现口型同步的可选方案

| 方案 | 说明 | 难度 |
|------|------|------|
| **视频生成时传入音频** | 使用支持音频驱动的视频生成 API（如部分数字人模型），在生成视频时同时传入 TTS 音频，让模型生成同步口型 | 需要更换视频生成接口 |
| **口型同步后处理** | 先用现有方式生成视频，再用 Wav2Lip / SadTalker / MuseTalk 等工具对人脸做口型同步重绘 | 需要引入新服务 |
| **数字人方案** | 放弃通用视频生成，改用数字人平台（如 HeyGen、D-ID、硅基智能）直接输入文本/音频生成带口型的视频 | 需要替换视频生成方案 |

---

## 适用场景说明

现有架构是"视频 + 配音 + 字幕"的简单叠加模式，适合：

- 旁白型内容（人物不需要开口说话）
- 对口型要求不高的短剧场景
- 以画面氛围为主的内容

如需精准口型同步，需在视频生成环节或合成环节引入额外的口型同步技术。
